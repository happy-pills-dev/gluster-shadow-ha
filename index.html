gluster-shadow-ha

A self-healing mirror of your working directory across two Linux machines — keeps working when they're separated, merges automatically when they reconnect.

MIT License Ubuntu 24.04 GlusterFS + Samba + CTDB No cloud dependency

The headline feature

Split-brain independence — no quorum required

When the link between nodes breaks, most two-node storage clusters degrade: they freeze, go read-only, or force you to manually resolve a conflict. This stack does none of that.

Node A keeps serving reads and writes through a local shadow buffer. Node B keeps serving from its own copy. Neither freezes. When the link comes back, GlusterFS self-heal merges both sides automatically — unattended.

What it can do

🔄 Real-time replication

Both nodes mirror every write in real time over your local network at full disk speed.

🪟 Windows drive mapping

Any client maps \\<VIP>\myshare as a drive letter. No client software needed.

⚡ Transparent failover

A node goes down → CTDB moves the VIP → clients reconnect. No data loss, minimal interruption.

🧲 Auto-merge on reconnect

After a partition, GlusterFS self-heal reconciles both sides. No manual merge step.

🥾 Hardened boot chain

Explicit systemd dependencies and a recovery watchdog bring the full stack up correctly after any reboot or power cut.

📣 Loud failures

Samba refuses to start if storage isn't ready — visible error, not silent empty directories.

Who it's for

Laptop + home server

Laptop is Node A. Home server is Node B. Leave home, keep writing. Come back, everything merges. No sync client, no conflict dialogs.

Two office workstations

Share a common project drive. One goes down for maintenance — the other keeps working. It catches up silently when it returns.

Dev + backup node

Production server plus a standby. Shadow layer absorbs writes during secondary failure. Drains in the background on reconnect.

Home lab NAS

Two repurposed mini-PCs. Full HA SMB share with floating IP. Under the cost of a consumer NAS, with complete visibility.

Quick start

# 1. Clone on both nodes
git clone https://github.com/happy-pills-dev/gluster-shadow-ha
cd gluster-shadow-ha

# 2. Edit the 15-line variables block
nano install.sh

# 3. Run on Node A
sudo ./install.sh --role node0

# 4. Run on Node B  (can run in parallel)
sudo ./install.sh --role node1

# 5. Create the GlusterFS volume — run ONCE from Node A
sudo ./install.sh --role node0 --step gluster-volume-create

# 6. Add a Samba user and verify
sudo smbpasswd -a youruser
./verify.sh
